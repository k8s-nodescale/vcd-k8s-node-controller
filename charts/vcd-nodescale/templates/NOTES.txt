The vCD credentials Secret is:

  kubectl -n {{ $ns }} create secret generic {{ .Values.vcd.existingSecret }} \
    --from-literal=url=https://vcd.example.com/api \
    --from-literal=user=svc-node-controller \
    --from-literal=password='***' \
    --from-literal=org=myorg \
    --from-literal=vdc=My-VDC-Name \
    --from-literal=insecure=false

Keys: url, user, password, org, vdc, insecure (optional).

  kubectl -n {{ $ns }} create secret generic {{ .Values.vsphere.existingSecret }} \
    --from-literal=url=https://vcenter.example.com \
    --from-literal=user=terraform@example.local \
    --from-literal=password='***' \
    --from-literal=insecure=true

Keys: url, user, password, insecure (optional). Only the connection lives here:
the datacenter, cluster, resource pool, folder, datastore and network of a pool

The Pod starts even while the Secret is missing: /readyz stays NotReady and
every affected pool reports CloudError naming the missing key, so the controller
never enters a restart loop over credentials.

Then create a K8sWorkerPool (see the README section "Writing a K8sWorkerPool
for an existing cluster" and config/samples/). The pool is cluster-scoped: no
metadata.namespace, and k8sworkerpool commands take no -n.

WARNING: once this controller is enabled, do not use Terraform to manage
worker count or worker LB pool membership; use the CRD instead.

{{- if and .Values.ui.auth.enabled .Values.ui.auth.createSecret }}

The chart generated the two accounts. Read the passwords once, then delete the
key so they stop existing:

  kubectl -n {{ $ns }} get secret {{ .Values.ui.auth.secretName }} \
    -o jsonpath='{.data.initial-passwords}' | base64 -d

  kubectl -n {{ $ns }} patch secret {{ .Values.ui.auth.secretName }} \
    --type=json -p '[{"op":"remove","path":"/data/initial-passwords"}]'

Rotate a password with "htpasswd -nB <user>" and put the hash into the
users.yaml key of that Secret; the page picks it up within
{{ .Values.ui.auth.refreshInterval }} without a restart.
